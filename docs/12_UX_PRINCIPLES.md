# UX Principles

## Purpose

Define the Phase-1 experience principles for clear, accessible, mobile-first
Persian RTL discovery and inquiry while preserving canonical Product and
commercial boundaries.

## Scope

This Draft covers information clarity, selector behavior, accessibility, responsive
interaction, error/unknown states, inquiry calls to action, Media inheritance, and
Admin manageability. It creates no screen, theme, page, content, asset, selector,
WordPress/WooCommerce configuration, or Runtime behavior.

## UX Baseline

- Design mobile-first in Persian RTL with correct BiDi behavior, keyboard access,
  visible focus, readable contrast, semantic labels, and screen-reader feedback.
- Product selection follows Family-configured axes and evidence-backed valid
  combinations; choices remain visible, reversible, and resettable. Unsupported,
  unknown, and unavailable are distinct states.
- Media resolves from exact Variant override to Appearance/Finish override to
  Family default only when material visual truth is preserved.
- Current commercial calls to action remain inquiry/operator-verification actions;
  no selector or content implies Price, stock, purchase eligibility, Cart, or
  Checkout.

Detailed orchestration belongs to the C006 Product Experience owner and existing
information/search/media/inquiry owners.

`MISSING_AUTHORITY_INPUT` — exact input: approved priority journeys and audiences,
usability evidence, accessibility conformance target and exceptions, device/browser
support, Persian content ownership, and measurable UX acceptance thresholds. It is
missing because C007 is architecture/documentation convergence, not UI research or
implementation. Affected domain/document: UX Principles and Product Experience
consumers. Safe behavior without it: preserve the baseline constraints and create
no UI or Runtime object.

journey-specific decisions remain separately gated.
